# Совместимость данных готовности и переход на 11 классов

Исправление находится в основной папке проекта. Текущий детектор `main` по-прежнему использует 13 классов и прежние веса. Конфиги обучения и файлы весов этой правкой не меняются.

## Поддержка SQLite уже сейчас

API читает результаты облётов и ручные проверки, сохранённые с `bank_readiness` или `readiness_level`. Внутри результата, проверки и записи журнала действий доступны оба имени с одинаковым значением. При наличии обоих ключей в базе приоритет у `readiness_level`, включая 0 и null. Отсутствующий уровень не вычисляется из стадии.

Карточка, история, стоимость, AI-факты и кнопка «Принять» используют подготовленные данные. Неполный результат возвращает HTTP 409 `STAGE_NOT_DETERMINED`. Исходные JSON в SQLite сохраняются без перезаписи; новые проверки добавляются отдельными записями. Пересоздание базы для поддержки переименования не требуется.

До обновления из `develop_ml` текущий контракт карточки и ручной правки остаётся `bank_readiness`, справочник — `/meta.bank_readiness`, AI-факт — `readiness.bank_readiness`. Это сохраняет работу текущего фронта и детектора. Новый формат хранения поддерживается на чтение заранее.

## Контракт следующей версии из develop_ml

- `readiness_level` — шкала 0/50/100 в карточке, результате, ручной проверке и истории.
- `/meta.readiness_levels` — справочник этой шкалы.
- `readiness.level` — факт для AI.
- `readiness_pct` — процент готовности; расчёт стоимости продолжает использовать его.
- Детектор: 11 классов (`classes@ml-v3`), исключены `paving` и `fence`.

Эти переименования уже подготовлены в `develop_ml`. Вместе с ними нужно сохранить поддержку чтения обоих форматов и проверку полноты результата перед принятием. Тесты `test_readiness_compat.py` проверяют оба варианта сохранённых данных и определяют актуальное поле по схеме текущей версии.

Сводки AI с другим набором фактов становятся устаревшими. История сохраняется; актуальную сводку можно запросить кнопкой «Обновить AI-сводку».

## Выпуск после обучения

1. Получите новые веса детектора с 11 ожидаемыми классами. Старые веса на 13 классов с новым конфигом несовместимы.
2. Сохраните резервные копии рабочей SQLite и старых весов.
3. Выпускайте код `develop_ml`, совместимость SQLite и новые веса детектора одной сборкой. Веса классификатора материала можно оставить прежними.
4. Укажите `READINESS_WEIGHTS` на новый файл. API и воркер должны читать одинаковую `.env`.
5. Остановите прежние API и воркер перед подключением рабочей базы; затем запустите новую пару процессов.
6. Проверьте `/meta`, старый облёт и его принятие, новый облёт, материал, стоимость и AI-сводку. Точность нового детектора проверяется после передачи новых весов.
